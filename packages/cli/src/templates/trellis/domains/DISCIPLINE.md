# 板块纪律（DISCIPLINE）

本文件是全板块共享的可执行纪律；日志协议另见 `WORKLOG-PROTOCOL.md`。按下列关键词裁决，不含糊：

- **必须** = 不做即违规；**禁止** = 做了即违规；**应当** = 默认要做，偏离须留痕；**避免** = 默认不做；**可** = 两可。

## 0. 基本盘

- `.omtre/domains/` 是**用户数据区**：`omtre update` 只补发缺失的骨架文件（本文件、`REGISTRY.md`、`WORKLOG-PROTOCOL.md`、`_scaffold/`），域内已有内容永不受管、不被覆写。
- 真值只在 git：未 commit 的旗、进度、日志一律不算数（见 `WORKLOG-PROTOCOL.md` 第 0 铁律）。
- 板块骨架 = `README.md`（首行旗位 + `## 进度`）+ `BOUNDARY.md` + `worklog/` + `review/`；首个 `NN-*` 随第一条真实需求同 commit 落地，不预建空文档。

## 1. 归口路由

每个 task 创建时先答「这件事归谁管」：

1. 动手前**必须**扫读 `REGISTRY.md`，判断产品代码改动属于哪个板块。
2. 能归口 → `task.json` 记 `meta.domain = <slug>`，`prd.md` 顶部写 `Domain: .omtre/domains/<slug>/`。
3. 无对应板块 → 先建板块（骨架 + REGISTRY 同 commit），再建 task；语义不得与既有板块重叠。
4. 确实无板块可挂 → `meta.domain` 留空，`prd.md` 顶部**必须**写 `Domain: none（<一句话理由>）`。
5. **归属不明 → 立即停工问用户**——这是安全网不是门禁，两档自主模式都拦。

domain-less 白名单（天然不挂板块）：纯文档/日志改动、当日拆除的临时探针（遗留即违规）、Omtre 自身基建/meta 类工作。

## 2. 施工旗协议

- 旗 = 板块施工权整体：`domains/<slug>/` 目录写权 **加上** 挂其 `meta.domain` 的 task 产品代码施工——同板块同时只许一个写者。读永远自由、不需旗。
- 旗行 = `README.md` 顶部单行（文件第一行，`head -1` 直读）：

  `旗: <平台>-<机器>-<写作者> · <task-slug或会话标识> · 自 <YYYY-MM-DD HH:mm>`

- 生效 = commit 入库（未提交 = 没插，与「未入库 = 不存在」同律）；拔旗 = 收工同一 commit 删旗行。
- 写者标识只要求唯一：`OMTRE_WRITER` 环境变量可覆盖默认的 `devin-<hostname>`——仓库卫生规则禁止机器名进提交时（如「commit 不含主机名」）**必须**配中性别名（如 `devin`）。
- 开工定序：查旗位 → 无旗（或走完腐旗流程）→ 插旗 + commit → 才动手写。
- 见**有效旗**（他人旗未腐）→ 不得碰该板块（含挂其上的 task 产品代码），向用户报告「谁、自何时、在哪个上下文施工」并等指示；接力/等候/强占由用户拍板——两档自主模式都拦。
- **腐旗判定三锚点**（自查，不拿事实问人）：① 旗时间戳；② `git log -1 -- .omtre/domains/<slug>/` 最后活动；③ 该写作者 `worklog/<平台>-<机器>-<写作者>.md` 最新条目时间。
  - `>24h` 且三锚点均无旗后活动 = **stale** → 可代拔：删原旗、插自己旗同一 commit 落地，自己 worklog 记「代拔 + 三锚点证据 + 原旗行原文」；只写自己文件，不碰原写作者的 worklog。
  - `<24h` 或有旗后活动 = **fresh** → 按有效旗流程处理。
- 同机同时插旗（互不可见）：先 commit 者赢；后写者发现冲突 → 撤自己旗、在自己 worklog 记「撞旗让位 + 对方旗原文」，转投他项或听指示。README 旗行与 `## 进度` 表**故意不** `merge=union`——撞旗产生真冲突 = 真实信号，不被 union 吞掉。
- 跨板块 task：每个受影响板块各插一旗，任一板块被撞即走撞旗流程；domain-less 工作不插旗。
- 旗真值 = 本仓已提交历史：无 remote 时不承诺跨机一致；跨机交接的权威凭据是 worklog 条目 ID + 对账，不是旗（配了 remote 后 push 自然传播旗，协议不变）。

## 3. 接手协议（读档链 + 复述先行）

新会话接手按级别走读档链：

- 同会话内续作：不走（上下文在手）。
- 接挂板块的 task → **全链**：`REGISTRY.md` → 板块 `README.md`（首行旗位 + `## 进度`）→ `BOUNDARY.md` → `NN-*`（`状态:已定版` 优先）→ `worklog/`（锚定 `[~]`/`[!]`/`🔄`/`⛔` 对账）→ 输出复述段。
- 接 domain-less task → **轻链**：task 工件（prd/implement）+ journal 摘要，无板块读档。
- 跨写者接手（旗是别人的/换机换人）→ 全链 + 腐旗三锚点检查。

**复述五行标准**——缺任一项 = 接手未完成、不得动手：

1. 当前 task 目录 + `status`；
2. 板块归属：`meta.domain` slug 或 `Domain: none（理由）`；
3. 涉及板块旗位状态：无旗 / 自己旗 / 他人旗（谁 + 自何时 + 处置）；
4. worklog 最新条目 ID + 其引用 commit hash 的 `git merge-base --is-ancestor <hash> HEAD` 核验结果；
5. 下一步动作一行。

对账裁决优先级（写死）：**git 历史 > worklog 条目 > README `## 进度`**；journal 是会话叙事，不进对账。对不上的处置见 `WORKLOG-PROTOCOL.md` 对账清单。

`omtre mem` 是可选补充源（查聊过什么），**不得**替代读档链、**不得**当事实源；顺序写死：先接手协议，后按需 mem。

## 4. 自主档位（B/C）

`config.yaml` 单键 `autonomy: gated | hands-off`，仓级，默认 `hands-off`，下次 context 拉取生效。

- **hands-off（C 档）**：建 task、`start`、commit plan、finish-work 全部自动过——事前审批改为事后否决，产物仍照常列给用户；归口自动。
- **gated（B 档）**：上述卡点照常问人。
- 接手协议是信息动作不是门禁：C 档自动跑完读档链 + 复述后继续施工，复述仍输出、只是不等点头。

**永远拦人（两档都拦）**：

1. 破坏性/不可逆操作（删库删表、`rm -rf`、force-push、改 git config 等）；
2. 密钥/凭证/真实外部副作用（发信、付款、外部 API 写操作）；
3. 有效施工旗冲突；
4. 归属不明答不出归口。

**用户口头急停永远优先**：任何明确要求停止自动化的指令压过模式设置（与 `no-omtre` 跳过关键词同族）。模式切换动作记 journal 留痕：谁在何时从哪档切到哪档。

## 5. 板块文件纪律

- `NN-<主题>.md` = 需求/约定文档（可多篇，编号顺延只增不改）：五段——现象（已发生可复核）/ 目标 / 方案与取舍 / 不做什么 / 验收口径（逐条可判定）；元信息行 `状态: 评审中|已定版` + 日期 + 作者。**禁写执行项、勾选、过程**——约定与施工分离。已定版后改动只能走「新 NN-* 或本文件修订 + worklog 记偏差」的文档链，禁静默偏离；prd/task 引用到文件级。
- `BOUNDARY.md` = 边界判例登记：三触发当日登记——用户明令允许或禁止、同一问题改 ≥2 次、反复纠正的偏好；条目 `B-<序号>` + 能做/不能做/原因/反复修改史/出处 + 登记人 + 日期；任何人接手先读，**禁删**。
- `review/` = 板块级评审：条目含 评审人/日期/对象（附提交号）/结论（`通过|驳回|待办(N项)`）/证据。**评审回灌必须走文档链**（评审 → NN-* → task 条目 → 执行），禁止从评审直接改码；task 级 code review 住 task 目录。
- worklog 规则全文见 `WORKLOG-PROTOCOL.md`——分写作者文件、开工开条目、收工一单制。
- **清理纪律**：需求文档、worklog、BOUNDARY、review 一律禁删；板块删除永远要用户批准。
- 权威分工：板块垄断领域约定与事实，task 垄断一次性施工，spec 垄断编码指南。冲突时：约定 `NN-* > prd`；`BOUNDARY > spec` 在其登记范围内；细粒度进度只认 task `implement.md`；领域事实只认 worklog。

## 6. 临界规则（违规速查清单）

- 无旗在他板施工 / 见有效旗硬写 / 改他人的 worklog 文件 → 违规。
- 板块骨架与 REGISTRY 登记不在同 commit / 登记遗漏 → 违规。
- `prd.md` 缺 `Domain:` 行（无论挂板块还是 `none`）→ 违规。
- 读档链没跑完 / 复述不达五行就动手 → 接手未完成。
- 从评审直接改码 / 在 `NN-*` 写执行项 / 删任何板块工件 → 违规。
- 「归属不明停工」与「复述不达标不动手」是两条并列停线，互不覆盖。
