# 板块施工日志协议（WORKLOG-PROTOCOL）

本文件是全板块共享的 worklog 协议；归口/旗/接手纪律另见 `DISCIPLINE.md`。

## 第 0 铁律

**不 push 等于没做；无 remote 时，不 commit 等于没做。** 真值只在 git 已提交历史——口头「做完了」、未入库的编辑一律不算数。换机/换会话第一件事：把仓库拉到最新。

## 1. 文件制：分写作者、单追加、永不互撞

- worklog 按写作者分文件：`worklog/<平台>-<机器>-<写作者>.md`（如 `devin-DESKTOP-ABC123-subagent.md`）。单写作者追加 → 合并恒不冲突（本目录已配 `merge=union`）。
- **只写自己的文件**：要纠正/评论他人条目，在自己文件里写新条目并引用其 ID；跨文件引用只用条目 ID。
- 文件内**倒序**，最新条目在顶。
- 查阅 = grep 全目录，不需要合并视图。
- 文件头三行：写作者身份（`<平台>-<机器>-<写作者>`）、本协议路径引用、「只写本文件；倒序；开工开条目、收工更新同一条目」。

## 2. 条目格式

标题行 = 全局唯一条目 ID：`[<task-slug或NN-*>]-<写作者>-<YYYYMMDD-HHmm>`。保留命名空间：`[misc]`（杂项）/`[handoff]`（交接，可声明取代旧条目）/`[design]`（设计阶段）。

条目九字段（缺项写「无」，不省字段）：

| 字段 | 内容 |
|---|---|
| **执行者** | 身份三元组 `<平台>-<机器>-<写作者>` + 一句角色说明 |
| **目标** | 本工作段要达成什么 |
| **上下文** | 仓/分支、相关 task 与板块、旗位状态 |
| **进展** | 做了什么；引用前序入库点写 `<仓>@<分支> <hash>` |
| **验证** | **可重跑的命令**，不是叙述（如 `git merge-base --is-ancestor <hash> HEAD`、测试命令） |
| **决策与坑** | 影响他人的决定、「下次会忘」的坑与环境事实 |
| **代码状态** | 逐仓写明 `已 push <仓>@<分支> <hash>` / `仅本地未 push` / `无 remote，本地 commit 即真值`；**只引前序 commit**——本条所在 commit 的 hash 写作时不可得，由 `git log` 自明 |
| **状态** | `🔄`进行中 / `✅`完成 / `⛔`受阻 —— 一一对应进度四态 `[~]`/`[x]`/`[!]`（`[ ]` = 未做） |
| **下一步** | 一行可执行动作 |

配套规则：

- 同一任务**滚动更新同一条目**，不新开。
- 条目落盘不挑 commit——生效以其入库 commit 为准，搭顺车 commit 允许。
- 代他人记条目须标「代记 + 依据」。
- 凭证/密钥只写存放位置，永不入库。

## 3. 何时写 worklog

写 worklog（板块轴）：

- 挂 `meta.domain` 的 task 施工——开工开条目、收工更新同一条目（产品代码施工的进展要回填板块战线）；
- 直接改动 `domains/<slug>/` 下任何文件。

只写 journal（会话轴）：domain-less 工作（基建、meta、纯文档）。journal 是会话叙事，**不参与对账**、不抢事实权威。

## 4. 收工一单制

收工 commit 一单装齐：**worklog 条目更新 + 板块 README `## 进度` 勾项 + 删旗行 + 代码改动**，同一 commit 落地。

顺序：先写簿记（条目标状态、记前序 hash、勾进度）→ 删旗 → 连同代码一并 commit。崩溃宁可少勾、不多勾。

commit 粒度：一条工作线一串 commit，不混线；message 写清「做了什么 / 为什么 / 怎么验证」；署名尾注随各仓惯例。有 remote 时 push 归 finish-work 簿记段统一做（工作 commit → archive commit → journal commit → push）；无 remote / 推送失败只警告不阻塞。

进度表勾项随 `NN-*` 条目落地时才写——骨架入库时表可空（空表即现状，不是欠账）；worklog 引用 commit 只引前序，自指不可达时 `git log` 自明。

## 5. 对账清单（接手/复核手跑）

裁决优先级（写死）：**git 历史 > worklog 条目 > README `## 进度`**。

1. `git pull`（有 remote）+ `git log -1 -- .omtre/domains/<slug>/` —— 板块工件可达。
2. 锚定进行中/受阻：`grep -rnE "\[~\]|\[!\]|🔄|⛔" .omtre/domains/<slug>/`——看全板标记，不凭文件顶部猜闲忙。
3. worklog ↔ README 进度按条目对账：勾了没证据 → 标 `[!]` 待人工裁决；worklog 有证据没勾 → 补勾。
4. **信任但核验**：条目引用的 commit 跑 `git merge-base --is-ancestor <hash> HEAD` 验可达；其「验证」字段命令重跑一遍（防幻影地基）。
5. 标 `[~]` 开新条目续做。

对不上时的处置：当前写作者在自己 worklog 记「对账差异 + 裁决依据 + 采用的修正」，进度表按核验结果修正。

## 6. 必记清单

- 状态变化（开工/收工/受阻/解除）；
- 影响他人或在途工作的决策；
- 「下次会忘」的坑与环境事实；
- **与文档的偏差**——修文档回灌，不静默偏离；
- **过渡态必须带死线**：关闭条件 + 最迟评估日，定期扫超期；
- 跨写者/跨机交接：引用对方条目 ID；
- 撞旗/让位/代拔：记三锚点证据 + 原旗行原文。
