# 板块登记表（REGISTRY）

板块 = 领域知识的持久归口：需求约定（`NN-*`）、边界判例（`BOUNDARY.md`）、施工事实（`worklog/`）、评审记录（`review/`）统一住进 `.omtre/domains/<slug>/`。本文件是全部板块的索引真源——归口判定、接手读档链、机械对账都从本文件扫起。

## 登记规则

- 行格式：`<板块slug>/ — ≤100字用途`，一行一板块，尾斜杠标识目录；新行**追加到文件末尾**。
- 建板块 = 建目录骨架 + 本文件登记一行，两者必须**同一个 commit** 落地；漏登 = 违规。
- slug：小写字母/数字/连字符；语义不得与既有板块重叠。板块删除永远要用户批准。
- 无对应板块时 AI 可自行创建：复制 `_scaffold/` 为 `domains/<slug>/` 起步。`_scaffold/` 是骨架模板目录，**不是板块**——不登记、不参与旗位/进度/对账。
- `domains/` 下每个板块目录在本文件必须有行；有行无目录、有目录无行都算违规（机械对账点）。

## 归属声明

`.omtre/domains/**` 是用户数据区：`omtre update` 只在文件缺失时补发骨架，域内已有内容永不比较、覆写或提示托管。

本文件是多写者 append 面 → `.gitattributes` 配 `merge=union`。
